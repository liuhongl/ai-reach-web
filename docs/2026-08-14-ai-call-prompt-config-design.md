# AI Call 提示词配置实施设计

状态：已确认，作为第一版实施与验收基准
日期：2026-08-14
涉及项目：`ai-reach-web`、`ai-call`

## 1. 目标

把现有“通用配置 / 场景配置”页面改造成以场景为主的提示词工作台，并打通配置、变量、任务名单、版本和实际外呼运行时。

本次成功标准：

1. 运营人员只编辑业务内容，不接触平台固定约束。
2. 页面保存的开场白、产品信息、场景提示词和变量在实际外呼中生效。
3. 不同租户的数据互不可见、不可修改。
4. 任务创建时锁定提示词版本；场景后续修改不影响已创建任务。
5. AI 生成或优化只产生候选内容，不自动保存或发布。
6. 历史版本可查看、对比、应用和删除，且不会破坏任务审计。

## 2. 第一版范围

### 2.1 包含

- 顶部可折叠的通用提示词模板。
- 场景选择、创建、编辑和保存。
- 独立开场白编辑区。
- 产品/服务信息编辑区。
- 六段式场景提示词结构。
- 开场白和场景提示词分别进行 AI 生成/优化。
- 业务变量定义、插入和原子删除。
- 根据场景变量生成名单模板、校验名单并保存变量快照。
- 草稿业务内容预览。
- 场景提示词版本管理。
- 租户隔离。
- 任务提示词版本锁定。

### 2.2 暂不包含

- 精确 300/500/800/1000 毫秒停顿。
- CosyVoice 或其他新 TTS 链路。
- 知识库、文件上传和“从知识库提取产品信息”。
- 提示词测试台或“测试此版本”。
- 模型提供商和模型选择器。
- 通用提示词的版本管理界面。
- 指标卡、趋势图、饼图等下钻能力。

第一版开场白仍由当前实时模型播报。标点可以形成自然停顿，但不承诺具体毫秒；页面不展示无法在运行时兑现的“插入停顿”按钮。

## 3. 当前实现事实

### 3.1 前端

- 页面位于 `src/pages/aiCallLab/promptConfig/index.tsx`。
- 当前开场白和场景提示词使用普通 `Input.TextArea`。
- 当前场景字段只有 `sceneCode`、`name`、`providerKey`、`promptText`、`openingMessage`。
- 通用提示词通过独立接口读取和保存。
- 当前预览读取已保存场景，不能预览未保存草稿。
- 当前项目没有直接依赖 Tiptap。

### 3.2 后端

- 场景配置保存在 `ai_call_prompt_profile`。
- 通用提示词保存在固定 `id=1` 的 `ai_call_prompt_common_config`。
- 当前场景和通用提示词均未按租户隔离。
- `BusinessPromptResolver` 当前会自动读取通用提示词并追加到场景提示词。
- `render_prompt_template()` 已支持 `{{camelCaseKey}}` 变量；缺少变量或值为空时会拒绝生成提示词。
- 当前没有场景提示词版本表。
- 当前任务快照只保存提示词 ID、名称、场景编码和来源，不保存版本或完整提示词快照。
- 运行时主要按 `sceneCode` 重新读取当前场景配置，因此已创建任务会受到后续修改影响。

### 3.3 名单

- 当前名单模板和校验只支持“手机号、客户名称”。
- 其他 Excel 表头会被判定为不支持。
- 校验行和正式外呼对象没有 `businessParams` 快照。
- 运行时目前只传递 `customerName`，没有传递整行自定义变量。

## 4. 页面结构

页面采用单列全宽分层布局，不使用三栏工作台。

### 4.1 通用提示词模板

- 位于页面最上方，默认折叠。
- 可以单独展开、编辑和保存。
- 提供“应用到当前场景”按钮。
- 应用是一次性复制，不是持续绑定。
- 内容复制到当前场景的“沟通规则”章节后，可继续单独修改。
- 再次应用时先展示差异，并确认是否替换现有“沟通规则”，不得重复追加。
- 通用模板不再由运行时额外自动拼接，避免与场景内容重复。

### 4.2 场景选择与基本信息

- 选择已有场景或创建场景。
- 编辑场景名称和场景编码。
- 不展示模型提供商、关联任务数量和“提示词来源”。
- `providerKey` 仅作为后端旧数据兼容字段保留，新建或编辑固定使用静态场景配置。

### 4.3 开场白

- 独立保存，不重复写入场景提示词正文。
- 支持插入业务变量。
- 支持 AI 生成/优化。
- 不支持精确停顿节点。
- 不要求“简洁版 / 自然版”等多版本切换。

### 4.4 产品/服务信息

- 第一版为独立多行文本编辑区。
- 用于保存产品事实、适用客户、核心能力、价值和不能承诺的内容。
- 运行时将该内容放在平台固定约束之后、完整场景提示词之前。
- 后续知识库完成后再评估自动提取，不预留无效按钮。

### 4.5 场景提示词

新场景默认生成以下结构：

```text
## 一、角色与任务

## 二、业务信息

## 三、沟通规则

## 四、对话流程

## 五、常见异议

## 六、完成与结束条件
```

现有提示词迁移规则：

| 新结构 | 现有内容来源 |
| --- | --- |
| 角色与任务 | 角色设定、沟通对象和业务目标 |
| 业务信息 | 本次外呼特有的活动、客群、收集字段和业务目标 |
| 沟通规则 | 回复长度、一次一问、术语识别、不得编造或承诺 |
| 对话流程 | 是否方便、介绍、答疑、意向推进和转人工条件 |
| 常见异议 | 价格、效果、试用、案例、私有化、数据安全、没空、没兴趣 |
| 完成与结束条件 | 无兴趣结束、有意向记录、转人工、闲聊收尾 |

“产品知识卡”、产品介绍重点、适用客户和核心能力从旧提示词中移入“产品/服务信息”；场景提示词的“业务信息”只保留本次外呼特有内容，避免重复。迁移只重排和去重，不修改原有业务事实；迁移前内容作为初始历史版本保留。

### 4.6 操作区

- `预览`：打开当前未保存草稿的业务内容预览。
- `保存场景配置`：保存后立即生效并生成新版本。
- 离开页面、切换场景或刷新时，已有未保存修改继续使用当前确认提醒。

### 4.7 历史版本

- 标题展示版本数量。
- 列表展示版本号、可编辑版本名称、创建方式、操作人和创建时间；版本名称默认使用场景名称。
- 操作包括：查看详情、对比当前、应用此版本、删除；当前版本不展示“应用此版本”。
- 应用历史版本会基于该快照生成一个新的最新版本，不覆盖历史记录。
- 当前最新版本不可删除。
- 被任务引用的版本只允许逻辑删除，任务审计仍可读取完整快照。

## 5. 变量设计

### 5.1 变量定义

第一版所有业务变量均按字符串处理，不增加“短文本”等变量类型。

```json
[
  {
    "key": "customerName",
    "label": "客户名称"
  },
  {
    "key": "companyName",
    "label": "公司名"
  }
]
```

约束：

- `key` 使用 camelCase，匹配 `^[A-Za-z][A-Za-z0-9_]*$`。
- `label` 使用运营人员可理解的中文表头。
- 同一场景内 `key` 和 `label` 均不可重复。
- 仅暴露业务变量；`targetId`、`attemptNo`、`lineId` 等系统上下文不可选择。
- AI 不得创建场景变量列表中不存在的变量。

### 5.2 编辑器交互

- 开场白和场景提示词均可插入变量。
- 前端显示中文标签，提交和存储仍使用 `{{companyName}}`。
- 变量是不可拆分的内联原子节点。
- 光标在节点前后按 Delete/Backspace、选中节点删除时，都一次删除整个变量。
- 不允许进入变量内部编辑单个字符。

实现时只引入 Tiptap 基础编辑能力和自定义变量节点，不迁移 Recov 的完整模板编辑器，不加入图片、表格、签章等无关扩展。

## 6. AI 生成与优化

### 6.1 模型职责

- 实时通话继续使用 `qwen3.5-omni-plus-realtime`。
- 提示词生成和优化使用百炼文本模型，默认 `qwen3.7-plus`。
- 新增独立后端配置：`AI_CALL_PROMPT_OPTIMIZE_MODEL=qwen3.7-plus`。
- 继续复用现有百炼 Base URL 和 API Key，不增加新的密钥体系。
- 前端不展示模型名称或选择器。

### 6.2 操作流程

- 内容为空时点击按钮：根据场景名称、产品信息、通用模板和允许变量生成内容。
- 内容不为空时点击按钮：自动优化当前内容，不要求先填写优化要求。
- 用户可填写可选要求后再次优化。
- 后端返回候选内容和警告，不直接写数据库。
- 前端展示原内容与候选内容对比。
- 点击“采用”只更新编辑器草稿；最终点击保存才生效。

### 6.3 输出校验

- 使用非思考模式和结构化 JSON 输出。
- 检查已有变量是否被删除或改名。
- 拒绝模型生成未定义变量。
- 开场白优化不得生成停顿节点。
- 场景提示词优化不得生成平台未提供的微信、预约、发资料、安排顾问等工具承诺。
- 调用失败、超时或输出校验失败时保留原文，不修改草稿。

## 7. 运行时提示词组装

第一版运行时顺序：

1. 后端平台固定约束。
2. 后端真实可用的转人工、工具和结束通话约束。
3. 产品/服务信息。
4. 完整场景提示词；其中“沟通规则”可能由通用模板复制而来。
5. 独立开场白约束。

规则：

- 平台、安全、工具、真正转人工和挂断约束由后端维护，不在业务页面或业务预览中展示。
- 通用提示词不再作为独立运行时段落自动追加。
- 场景可以配置“何时建议转人工”“何时业务完成”，但不能修改真正的转人工和挂断机制。
- 微信、预约、发送资料、安排顾问等动作，只有存在真实工具且调用成功后才允许确认完成。

## 8. 数据设计

### 8.1 `ai_call_prompt_profile`

保留现有表作为当前生效投影，增加：

- `tenant_id`：非空，场景租户。
- `product_info`：产品/服务信息文本。
- `variables_json`：变量定义 JSON。

唯一约束从 `scene_code` 调整为 `(tenant_id, scene_code)`。

继续保留：

- `prompt_text`：带 `{{key}}` 标记的场景提示词纯文本。
- `opening_message`：带 `{{key}}` 标记的开场白纯文本。
- `provider_key`：旧数据兼容，新配置固定为 `static_profile`。

### 8.2 `ai_call_prompt_common_config`

- 增加 `tenant_id`。
- 每个租户一条通用模板。
- 唯一约束为 `tenant_id`。
- 第一版不增加版本表。

### 8.3 `ai_call_prompt_profile_version`

新增版本表：

- `id`
- `tenant_id`
- `profile_id`
- `version_no`
- `version_name`：默认使用保存时的场景名称，可单独修改且不改变版本快照
- `snapshot_json`
- `creation_method`：`manual`、`ai_generated`、`ai_optimized`、`restored`
- `restored_from_version_id`
- `created_by`
- `created_by_name`
- `created_at`
- `deleted_at`

唯一约束为 `(tenant_id, profile_id, version_no)`。

`snapshot_json` 保存：场景名称、场白、产品信息、场景场景编码、开提示词和变量定义。保存场景与创建版本必须在同一事务内完成。

### 8.4 名单校验和任务对象

- 校验行增加 `business_params_json`。
- 正式外呼对象增加 `business_params_json`。
- 任务的 `config_snapshot_json` 增加 `promptVersionId`、`promptVersionNo` 和完整 `promptSnapshot`；运行时直接使用该快照。
- 运行时外呼命令传递整份 `businessParams`，不再限定只有 `customerName`。

## 9. 租户与任务版本规则

### 9.1 租户隔离

- 所有提示词配置、通用模板、版本查询和修改接口必须从登录用户获取 `tenantId`。
- 不接受前端传入的 `tenantId` 作为授权依据。
- 所有仓储查询同时包含 `tenant_id` 条件。
- 场景编码只要求租户内唯一。
- 预览、AI 优化、版本详情和任务模板下载同样执行租户校验。

### 9.2 任务锁定版本

- 创建任务时读取场景最新有效版本并写入任务快照。
- 任务内所有号码、重试和异常补呼都使用同一版本。
- 场景后续保存只影响新建任务。
- 历史版本被逻辑删除也不影响已创建任务。
- 旧任务没有版本快照时标记为 `legacy`，不得伪造历史版本。

## 10. 名单模板与校验

- 下载名单模板必须携带所选场景或提示词配置 ID。
- 模板固定包含“手机号”，并包含该场景实际引用的业务变量中文列名。
- `customerName` 如果被开场白或场景提示词引用，则“客户名称”成为必填列；未引用时不强制。
- 上传时将中文列名映射到变量 `key`。
- 提示词引用的变量缺少列时，整批校验失败并指出缺失列。
- 某行引用变量为空时，该行失败并展示 Excel 行号和变量中文名。
- 未被场景定义的额外表头继续拒绝，避免静默吞掉错误字段。
- 通过校验的每行变量值复制到正式外呼对象，后续原 Excel 文件变化不影响任务。

## 11. 接口调整

沿用现有 `/ai-call` 接口体系，不新增第二套服务。

### 11.1 场景与通用模板

- 扩展现有场景 GET/POST/PUT，增加 `productInfo`、`variables` 和版本摘要。
- 扩展通用模板 GET/PUT，改为租户范围。
- 现有场景保存接口在同一事务中生成新版本。

### 11.2 草稿预览

扩展 `POST /ai-call/prompt-profiles/preview`：

- 接收未保存的 `openingMessage`、`productInfo`、`promptText`、`variables` 和样例参数。
- 返回业务预览和变量校验结果。
- 不返回平台固定约束全文。
- 使用与运行时相同的业务内容渲染和变量校验函数。

### 11.3 AI 优化

新增 `POST /ai-call/prompt-profiles/ai-optimize`：

- `targetType`：`opening` 或 `scenePrompt`。
- `currentContent`：当前草稿。
- `sceneContext`：场景名称、产品信息、通用模板和允许变量。
- `instruction`：可选的再次优化要求。
- 返回 `candidateContent` 和 `warnings`，不保存数据。

### 11.4 版本

- `GET /ai-call/prompt-profiles/{profileId}/versions`
- `GET /ai-call/prompt-profiles/{profileId}/versions/{versionId}`
- `PATCH /ai-call/prompt-profiles/{profileId}/versions/{versionId}`：只修改版本名称
- `POST /ai-call/prompt-profiles/{profileId}/versions/{versionId}/apply`
- `DELETE /ai-call/prompt-profiles/{profileId}/versions/{versionId}`

版本对比在前端取得当前和历史详情后完成，不新增仅用于展示的后端对比接口。

### 11.5 名单模板

扩展现有名单模板下载接口，增加 `promptProfileId` 参数；后端根据当前租户、场景变量和实际引用生成 xlsx。

## 12. 数据迁移

实施前先只读统计现有场景、通用提示词、任务引用和租户数量。

迁移前不得存在仍会执行的 `SCHEDULED`、`RUNNING`、`PAUSED` 或重试等待任务；如果存在则阻止迁移，先完成明确处置，不能让运行中的任务跨越提示词语义切换。

迁移规则：

1. 根据现有任务的 `tenant_id + prompt_profile_id` 找出实际使用关系。
2. 一个全局场景被多个租户使用时，为每个租户复制一份当前内容。
3. 每个租户复制一份当前通用模板。
4. 每个迁移后的场景生成 `v1`，创建方式标记为 `manual`，备注为历史数据初始化。
5. 现有任务不补造版本；保留原任务字段并标记为 `legacy`。
6. 新任务从迁移完成后的版本锁定逻辑开始执行。
7. 迁移脚本必须可重复检查且不可重复插入版本。

上线前必须核对无法归属租户的孤立场景；不得默认归入任意租户。

## 13. 分阶段实施

### 阶段 A：后端租户、数据和版本闭环

- 数据迁移和模型调整。
- 场景、通用模板、版本和草稿预览接口。
- 移除通用提示词的运行时自动追加。
- 任务创建锁定版本。

验收：两个租户互不可见；保存生成版本；旧任务不被伪造；新任务保持版本不变。

### 阶段 B：提示词页面和 AI 优化

- 单列页面结构。
- 现有内容迁入六段结构。
- 通用模板应用。
- 产品信息、预览、保存和版本历史。
- 开场白与场景提示词的 AI 生成/优化。

验收：候选内容不会自动保存；变量和业务事实不被静默删除；应用旧版本生成新版本。

### 阶段 C：变量编辑器和名单闭环

- 原子变量节点。
- 动态名单模板。
- 上传映射、缺列和空值校验。
- 校验行、正式对象、外呼命令中的变量快照。

验收：变量一次删除；缺列和具体空值行被阻止；实际运行时渲染正确值。

### 阶段 D：运行时通话控制

- 240 秒开始收尾。
- 290 秒播放固定结束语。
- 300 秒安全结束。
- 最多 15 个有效客户轮次。
- 无回应执行三次 8 秒策略。
- 连续 3 轮闲聊后收尾。
- 所有正常策略结束均先说结束语，再挂断。

该阶段不引入 CosyVoice，不实现精确停顿。

## 14. 测试与验收

### 14.1 后端

- 场景、通用模板和版本的租户越权测试。
- 场景保存与版本创建的事务测试。
- 应用历史版本和逻辑删除测试。
- 草稿预览不读取旧保存内容的测试。
- 通用模板不再重复拼装的测试。
- AI 优化超时、非法 JSON、变量丢失和新增未知变量测试。
- 名单缺表头、空值、额外表头和变量映射测试。
- 任务版本锁定和重试沿用版本测试。

### 14.2 前端

- 通用模板默认折叠和应用确认。
- 场景切换未保存提醒。
- 六段结构和现有内容迁移展示。
- AI 候选对比、采用和取消。
- 变量插入、原子删除和序列化。
- 草稿预览、保存和版本数量。
- 历史版本详情、对比、应用和删除限制。
- 不同权限和无权限状态。

### 14.3 运行时

- 新任务创建后修改场景，原任务仍使用锁定版本。
- 同一任务的重试使用同一提示词和变量快照。
- 开场白和场景提示词引用名单变量后正确渲染。
- 平台固定约束仍生效，但不在业务预览中展示。
- 转人工失败兜底不重复播报、不承诺未真实创建的后续动作。
- 通话控制先播结束语再挂断。

未经明确授权，不进行真实号码外呼；运行时先用单元测试、集成测试和白名单环境验证。

## 15. 回滚

- 数据库变更使用新增列和新增表，不直接删除旧字段。
- `provider_key` 和旧任务字段保留一个兼容周期。
- 前端失败时可回滚到旧页面，新增数据不影响旧字段读取。
- 后端切换前保留通用提示词旧拼装代码的版本回滚点，但线上同一版本只能启用一种拼装方式，禁止双重追加。
- 新任务版本锁定上线后不回写或改写已创建任务快照。

## 16. 明确不再讨论的第一版决定

- 以场景配置为主。
- 通用提示词位于顶部并默认折叠。
- 通用提示词应用到场景是一次性复制，不是持续绑定。
- 保存后立即生效并生成版本。
- 场景和通用模板按租户隔离。
- 任务创建时锁定提示词版本。
- AI 优化使用独立百炼文本模型，实时语音模型不承担该职责。
- 第一版不做精确停顿和 CosyVoice。
- 第一版不接知识库、不增加测试此版本、不展示平台固定约束。
