# AI Reach 生产构建环境校验设计

## 背景

AI Reach 的 RuoYi 登录接口要求请求加密。若生产构建缺少加密配置，静态页面仍能正常发布，但登录请求不会携带 `encrypt-key`，后端会拒绝登录。

## 目标

执行 `npm run build` 时，在 Umi 构建开始前校验登录所需环境变量。配置不完整时立即失败，避免生成和发布不可登录的静态包。

## 校验规则

构建必须同时满足：

- `UMI_APP_ENCRYPT` 严格等于 `true`；
- `UMI_APP_RSA_PUBLIC_KEY` 非空；
- `UMI_APP_RSA_PRIVATE_KEY` 非空；
- `UMI_APP_CLIENT_ID` 非空。

校验失败时只输出缺失或无效的变量名，不输出变量值。校验成功后继续执行现有 `max build`。

## 实现边界

- 增加一个无第三方依赖的 Node 校验脚本；
- 通过 npm 的 `prebuild` 生命周期自动执行；
- 不修改开发服务器启动方式；
- 不提交 `.env`、密钥或客户端凭据；
- `/dev-api` 和 SSE 继续使用现有默认路径，不纳入强制校验。

## 验证

- 缺少任一必需变量时，校验脚本以非零状态退出；
- `UMI_APP_ENCRYPT` 不是 `true` 时，校验脚本失败；
- 四项配置完整时，校验通过；
- 使用现有安全环境配置执行 `npm run build`，完整构建成功；
- 现有测试和 TypeScript 检查继续通过。

## 发布影响

本改动只阻止错误构建，不改变运行时接口、菜单、权限或业务行为。历史发布包和回滚目录不受影响。
